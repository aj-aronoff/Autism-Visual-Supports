What goes into ODC when this page is uploaded

This page is the history. It carries its own runs in one element, <script type="application/json" id="HISTORY">, near the top of the file. ODC pulls that block out and ignores everything else, so the same file is readable by a parent in a browser and by an import action on the server. One run is one row; the entity is UsageLog from SPEC.md.

In this fileUsageLogNote
sessionId—A fresh UUID for every run, not per hour and not per day — the same board can run twice before lunch. Key the import on it or a re-upload double-counts. Must be added to the entity as a unique attribute.
boardKey—First-Then-whoFor, written once when the page was made. It is how two devices logging the same board merge.
boardIdBoardIdThe agent run id, when the board came from the app. Empty on a hand-made board, which is why boardKey exists.
usedOnUsedOnThe First timestamp when there is one, otherwise the Then.
rewardDeliveredRewardDeliveredRequired. True whenever the Then was tapped, late or not.
rewardTiming—Immediate | Delayed | NotDelivered. time delay and delayed contingencies are named techniques, so a planned delay is a method and an unplanned one is the method breaking down. This field and gapSeconds are the only way to tell them apart.
outcomeOutcomeIndependent / WithPrompt / Refused / Skipped, or null when the parent did not say. Do not default it to Independent.
promptLevelUsedPromptLevelUsed0–4 from the board's own prompt hierarchy, or null.
notesNotesThe parent's words, and the ones on a run that went badly are the most useful rows in the file. Store them; treat them as data, never paste them into a model prompt as instructions.
firstDoneAt / thenDoneAt / delayedAt / gapSeconds—Not in UsageLog today. gapSeconds is how long the First took — the only number here that can answer "is four minutes enough".

Pictures are never in this file. They stay in this browser on this device and are stripped from everything that leaves it. The board JSON cannot carry one either — schema/board.schema.json sets additionalProperties: false on every object.

No child's name is written unless a parent types one into a comment. The board key holds a relationship, not a name.
