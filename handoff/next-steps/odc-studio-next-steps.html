Seven of the nine first-login checks returned last night. 04

Five traps that are specific to working inside Studio

  1. The request meter is live and it started last night. Claude Haiku 4.5 reads 0 of 1000 requests, which is the Licensed Customers row, so the cap is 2,100 requests across the three models. It is a total, not a rate, and nothing refills it. Every test run of an agent spends permanently — so test the flow with a stubbed response first, and only then call the model.
  2. Trial models exist in the Development stage only. Do not publish to Production during these checks. Two stages exist and both are Online, but the demo runs from Development because that is where the models are — that is settled now, not a choice left open.
  3. An ungrounded agent does not fail. It answers plausibly out of the model's own weights, with no error anywhere. A knowledge base is scoped to all stages in the organization — corrected 1 November, the repo had it per stage — but run one real retrieval in the stage you record the demo in anyway, because this is the failure that is silent.
  4. Every prompt belongs in a Setting, not in the flow. SystemPrompt and UserPrompt per agent as ODC Settings means a prompt can be retuned in the Portal without republishing. On 8 November, during the UX pass, that is the difference between a tweak and a redeploy.
  5. The .oml files are a proprietary binary from a downloaded bundle. Import them into Studio; do not try to read, unpack or script them, and keep your own scripts out of LoanReview/exercises/. Each bundle was extracted into its own empty directory on purpose.
